## 改动

1. 仅硬件门控后 stage=B 的解码器启用输出合并。每次drain使用零超时取输出；批内保留一个待显示buffer，取得新buffer时短暂同时持有两个，旧的随即归还且不显示；队列暂空就立刻提交最后一张，连续最多取8个buffer后提交，不额外睡眠或等待凑批。
2. 不丢弃压缩帧，不改变H.264参考链。配置buffer和空EOS不覆盖最后一张有效画面；关闭或异常时归还持有buffer而不显示。旧的250ms失链/关键帧恢复保留，C软恢复和接收队列保持关闭。
3. 解码线程新增5秒聚合：QUEUE_AGE、INPUT_WAIT、INPUT_COPY、INPUT_SUBMIT、OUTPUT_POLL、CODEC_AGE、OUTPUT_RELEASE，以及decoded/rendered/superseded。时间单位为微秒，值为平均/最大。INPUT_WAIT包含等待输入时的输出排空，不能与OUTPUT阶段简单相加。CODEC_AGE从应用赋给输入的时间戳至取出输出，是应用观察的驻留时间，包含提交调用，不是纯硬件解码时间。QUEUE_AGE在B从媒体sink入队开始，不包括先前网络读取和解密。rendered仍表示提交显示，不是屏幕物理帧率。
4. 事件通道新增锁等待、编码、TRACE格式化/回调、加密、socket写入的独立平均/最大计时。LOCK_WAIT只覆盖公开sendCommand入口，内部已持锁路径无该样本，日志附各阶段n。写入包含flush，失败写入也记录已等待时间；无法就绪或加密失败时各阶段样本数可能不同。统计在事件锁内归属，实际日志写入在锁外。原日志及加密/nonce顺序不改。
5. 保留input1的触控队列与快速hex、connect2启动恢复、USB默认授权、原分辨率/帧率/音乐缓冲偏好。没有将帧率降为30或强制改系统栏，没有改变USB控制请求或系统配置。
