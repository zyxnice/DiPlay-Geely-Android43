# ADR-0003：8600 有线连接前自动准备运行时 USB 状态

状态：Accepted（实现范围已由用户要求明确；实车验收待完成）

日期：2026-10-27

作者：Codex

最后修改：2026-10-27

## 上下文

10月26日实车依赖临时 Host、SDP、供电及解除 snd-usb-audio 占用才连通 CarPlay；
运行时处理未进 APK，10月27日用户报告再次无法连接，并要求日常无需 ADB。
今天无法连接的实时状态尚未采集，不能将已知复发机制等同于今日唯一根因。
用户要求本轮先做好修复包，不操作实车。

## 决策

在现有 USB 访问层增加独立运行时准备所有者 `GeelyUsbRuntimeRecovery`，由 Controller 的
有线初始发现阶段调用，重枚举/已打开数据通路不调用。仅新 USB2 metadata 与
API18/C3ALFUS/06.03.08600.H53.00060 的交集启用。复用 OEM 桥和私有 helper DEX 打包通道，
助手执行固定的临时 Host/电源/SDP 策略，带绝对截止时间、可撤销租约和独立故障恢复预算。

在 `H52UsbConfigurationFix` 的现有配置选择入口，登记并识别两种授权 FD 来源，
已知 05ac:12a8/config2→6 使用单独原生入口；只有 EBUSY 且绑定 snd-usb-audio 接口0/1时解绑重试。
未知占用失败，不抢占别的用户态连接；失败尝试恢复驱动。原 `configure()` 及其他机型保持原语义。

本记录补充 ADR-0001：其 FD 获取身份协议仍有效；“不修改 USB role”仅适用于 USB1 的旧范围。
USB2 的新 opt-in 允许上述临时准备，仍不修改固件、节点权限、persist 属性、持久ADB设置或系统应用。
运行时移除adb USB function可能断开当前有线ADB；这不是持久修改，重启按原持久配置初始化。

## 后果

正面：将已知连接前置条件收归应用，不再依赖每次现场手动脚本；普通构建、无线和其他设备保留原行为。
负面：依赖原厂高权限桥及私有固件语义；不能撤销已进入内核的单次调用，故障回滚仍需实车验证。
不改变系统启动默认值意味着每次启动仍需由应用准备，而不是系统始终保留 CarPlay 角色。
本轮包不修复既有音画卡顿，不承诺无需 iPhone 授权或能抢占其他投屏应用。

## 替代方案

- 永久改 init/persist 或开机 root 脚本：扩大系统范围，可能影响维修/原厂USB，未采用。
- 继续 ADB 手工处理：不符合用户需求。
- 只移植通用驱动解绑：不能解决尚未枚举时的角色/充电条件，且范围过宽。
- 同时改共享单 FD 与传输层：当前没有对应失败证据，不纳入。

## 撤销条件

如果实车 OEM 助手无法被应用调用、角色准备无法可靠回读或出现未控制的会话/供电影响，停止启用
新 metadata并回退同签名USB1；只读收集实际状态再修复，不扩展固件或驱动范围。
