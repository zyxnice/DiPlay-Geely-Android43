# ADR-0001：8600 使用应用内受限 USB FD 访问路径

状态：Accepted（用户已批准应用旁路方案；实车验收未完成）

日期：2026-10-26

作者：Codex

最后修改：2026-10-26

## 上下文

本地H53/API18固件的Android USB缓存存在过滤及事件恢复限制。正常UsbManager.openDevice拒绝未收录节点，普通App又没有raw USB节点权限。原厂usbprotect/native-commond有root命令执行通路，但只返回短文本；不能当作FD接口。用户要求仅改DiPlay并交付独立测试APK，不改固件、不用模拟器。

## 决策

仅在测试构建明确开启且匹配H53/SDK18时，自扫内核Apple设备，使用原厂桥启动App附带的短生命周期受限助手，通过验证peer UID和nonce的本机FD通道取得真实USB FD，再构造API18连接对象。保留正常Manager路径；完整描述符解析和FD来源由专属访问层拥有。重枚举后重新确认身份。只允许Apple USBMUX/iAP2目标，不操作HID，不改节点权限、永久属性或USB role。不提供任意命令接口或su自动降级。

## 后果

正面：不刷固件即可绕开Framework收录门禁，复用既有USB传输；正常构建不启用；日志能区分内核未发现、桥失败和数据路径失败。

负面：增加API18非公开入口和受限特权助手维护；仍依赖实车原厂服务可达性、安全策略和内核枚举；主机测试不能证明CarPlay实车成功。

## 替代方案

- 只加VID或重试：不能打开被Manager漏收录的节点。
- 修改framework/内核：超出用户边界。
- chmod/chown全局USB节点或系统签名：扩大权限或需改系统，不采用。
- 完全另写USB/iAP2栈：无必要，现有fd-based transfer可复用。
- 自动su：未确认车机具备能力，会增加权限与交互，不作为此测试路径默认行为。

## 撤销条件

原厂桥不适用或出现未受控权限/FD泄漏时禁用测试metadata或卸载独立测试App；正常P21及固件保持不变。若有受支持的公开USB FD API，重新评估非公开构造器路径。
