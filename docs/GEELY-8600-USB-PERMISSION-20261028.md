# 8600 USB 默认授权修复

## 问题与边界

用户报告连接时反复出现VPN授权和USB访问授权，两者不是同一权限。
19:35附近车机 `dumpsys usb` 已有Apple 1452:4776到本应用的默认关联，当前设备权限UID为10062。
原B APK及common资源只登记CH341（6790:21778），没有Apple USB attach过滤器。
本固件UsbSettingsManager先以资源过滤器生成匹配活动，再从匹配活动中查找默认包并授权；
因此仅有默认偏好、没有匹配活动，不能在重新枚举时复用默认选择。

## 修复

仅新增 `mobile/src/geelyUsb/res/xml/usb_device_filter.xml`：保留CH341，添加Apple VID1452，
范围与现有 `IphoneUsbMatcher.appleVendor()` 一致。普通构建不变。
系统仍负责首次许可及默认选择；没有关闭USB权限检查、代写系统设置或引入特权授权接口。
默认选择后，USB插入可能正常自动打开CarPlay页，这是系统attach处理的预期行为。

本固件在应用更新时可能清除相容USB默认关联。覆盖安装后的第一次应正常勾选
“默认情况下用于该 USB 设备”并确认，再验收后续重插。默认偏好包含VID/PID及设备类信息，
不同手机或不同枚举身份可能仍需首次确认。

VPN已核对：`requestVpnConsent()`先调用系统prepare，仅需授权时才弹窗；当前固件的
Vpn.mPackage保存在系统进程内存，普通DiPlay进程重启不会必然清除，系统重启会重置。
本晚19:31重启DiPlay后未再遇到VPN授权并成功创建通道，但媒体TCP握手仍有独立故障。
本补丁不承诺VPN跨车机重启免授权；“我信任此应用”不是永久许可选项。
