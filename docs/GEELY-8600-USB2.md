# 8600 USB2 自动连接准备测试包

2026-10-27。目标：打开 DiPlay 后由应用准备 USB 连接，日常使用无需手动 ADB 改配置。
**本包尚未实车验收，不声明已彻底修复。音画卡顿不属于本包修复范围。**

## 使用

1. 在停车状态下，将 USB2 覆盖安装到原“DiPlay 8600 USB测试”。包名保持
   `com.shihab.diplay.repair1.geely8600`；versionName 为 `0.2.10-H53-USB2`，versionCode 29。
   使用本机与 USB1 相同的签名，保留设置和配对数据；签名不匹配时停止安装，不要求卸载清数据。
2. 打开该测试应用，选择有线连接，使用原先验证成功的 USB 口和数据线连接已解锁 iPhone。
   手机首次提示信任或 CarPlay 授权时确认。若旧版 DiPlay 或其他投屏程序正在运行，请先退出它。
3. 每次进入有线发现阶段，程序检查实际角色、供电、充电模式及保护状态，按需准备 Host/SDP。
   配置切换时自动处理已确认的原厂音频驱动冲突。安装后无需运行仓库里的 ADB 修改脚本。
4. 连接失败时保存应用连接日志。请保留 `runtime=`、`8600 configuration`、`errno` 等信息。
   不要根据一个失败码关闭系统保护、删除系统应用或改持久属性。

## 自动处理边界

- 只在 USB2 变体明确 opt-in，并同时匹配 Android API18、BOARD=C3ALFUS、
  DISPLAY=`06.03.08600.H53.00060` 时启用；普通构建与无线连接不调用准备助手。
- 原厂 `usbprotect` 只启动随包提供的短期助手。助手仅能准备本平台固定的运行时 USB 节点，
  不接受任意 shell、属性名、节点路径或驱动名。先检查过流状态，异常立即停止。
- 按需设置 `sys.usb.config=accessory,ncm` 并等待 role0，打开 OTG 供电并设 SDP。
  不修改 `persist.sys.usb.config`、持久 ADB 设置、固件、系统应用或节点权限。
  切换到 `accessory,ncm` 会移除运行时 USB ADB 功能，可能断开当前有线 ADB；重启按原持久配置初始化。
  SDP 写入沿用本固件 `UsbProtectProvider` transaction8 参数2实际使用的同一节点/值。
- 不在重枚举、配对或播放过程中切换角色；已在 role0 的 Apple configuration6 保持原状。
  等待时优先本地读状态；修复间隔至少5秒，每个连接实例最多3次实际状态修复，系统反复回切时报告错误。
- 关闭连接会撤销该次准备的私有租约；助手在状态写入前验证租约和绝对时间。
  正常预算6秒，故障恢复额外1.5秒，进程最长8秒。已经进入内核的单次调用无法撤销，
  原厂服务/内核卡死也无法保证回滚成功；日志会保留失败，不把未回读状态当成功。
- 配置 `2→6` 遇到 `EBUSY` 时，只通过已打开并授权的 USB fd 检查 `05ac:12a8`，
  仅处理接口0/1上的 `snd-usb-audio`。检查到其他驱动、其他应用的 `usbfs` 占用则停止。
  解绑或重试失败时尝试重新绑定本次已解绑的驱动，不卸载全局音频驱动，不走 `su` 降级。
  Linux 3.0 的驱动查询与解绑不是同一原子操作，故仍需避免多个投屏应用同时争抢该设备。
- 不引入全志 T3 的单 fd 共享方案：当前8600已有双fd链路成功证据，尚无其二次打开故障证据。

## 晚间通过手机热点与 Termius 验收

用户计划使用此前已建立的反向转发方式安装；目前这是待执行计划。

1. 停车后保持手机热点、车机联网和 Termius Remote Forwarding 开启；恢复本机到中转服务器的转发。
2. 通过本机 `127.0.0.1:15555` 的 ADB 通道只读确认车机身份、现装包版本/签名和当前 USB 状态。
   不预先运行旧版角色或驱动解绑脚本，以便验证 USB2 自己完成连接准备。
3. 使用与USB1签名一致的USB2包覆盖安装（保留数据），打开测试应用并插入已解锁iPhone。
4. 分别记录首次连接、拔插重连、车辆正常关机再启动后的连接结果；保存应用日志并确认画面、声音、触摸。
   仅首次连通不能替代冷启动/拔插验收；音画卡顿另行记录。
5. Termius掉线或ADB离线只说明采集通道需恢复，不据此判定CarPlay失败。

## 回退

先退出 USB2；可用同签名 USB1 APK 覆盖安装，保留设置，不需要卸载或清数据。
USB2 未修改持久 USB 属性。运行时准备失败会尝试恢复本次改动并回读；内核/原厂服务失联时
不能保证恢复，使用车辆正常关机再开机恢复原厂初始化，再保存日志排查。不要在行驶中测试。
回退 USB1 也会回到之前需要手工准备连接的行为，不表示它解决了重复连接问题。
